## 원칙 1. 상태는 말이 아니라 색·배지·아이콘으로 말한다 ★ [6/6] · 약 150건

시스템이 아는 상태(접속/미접속, 읽음/안읽음, 제출/미제출, 잠김, 방장, 녹화중, 시청중)는 **문장으로 설명하지 않고 색·테두리·점·배지 숫자·아이콘**으로 즉시 읽히게 만든다. **안 보이면 그것 자체가 버그다.**

- 미접속 사용자는 회색으로 죽인다 (그리고 그 회색 톤을 두 번 미세조정할 만큼 신경 쓴다)
- 접속/해제 시 색이 **실시간으로** 바뀌어야 한다 — 새로고침해야 반영되면 버그
- 권한 없는 기능엔 자물쇠, 미제출자 수는 배지 숫자, 방장은 왕관, 남이 내 화면 보는 중이면 표식

**하위 규칙 — 복원**: 화면이 재생성돼도 그 표시는 **반드시 복원**된다. 좌석을 다시 그렸더니 미읽음 배지가 사라지는 것은 원칙 1 위반이다.

**확인 질문**: *"이 화면만 보고 지금 무슨 일이 벌어지는지 알 수 있나?"*

## 원칙 2. 느리면 버그다 — 체감 반응성은 UX 범주 ★ [6/6] · 약 90건

기능이 정확히 동작해도 **클릭에 딜레이가 있거나 창이 얼거나 깜빡이면 결함**으로 취급한다.
성능 커밋의 90%가 백엔드 최적화가 아니라 "렉 제거·버벅임 제거·멈춤 제거" 같은 **체감 언어**로 쓰여 있다.

**해법 레퍼토리** (이 순서로 검토):
목록 가상화 → 표시 개수 상한(예: 100) → 비동기·UI 스레드 밖으로 → 부분 재구축(전체 재생성 금지) → lazy loading → 캐시 → 디바운스

- 창 열 때 렉 = 목록을 통째로 그리고 있다는 뜻 → 가상화 + 개수 제한
- UI 무반응 = 동기 호출이 UI 스레드를 잡고 있다는 뜻 → 비동기 전환
- 파일 읽기·직렬화·압축은 **절대** UI 스레드에서 하지 않는다

**단, 안정성 > 부드러움.** 프레임을 올렸다가 불안정해지면 되돌린다.

## 원칙 3. 가려지거나 잘리면 즉시 고친다 ★ [6/6] · 약 80건

버튼·테두리·열·글자가 다른 UI에 가리거나 화면 밖으로 밀리면 **다른 무엇보다 먼저** 잡는다.
**"보이지 않는 UI = 없는 UI".**

전형적 사고 패턴:
- 하단 독바·고정 바에 버튼이 가림 → 모달 하단에 그만큼 여백
- 화면이 작으면 제출 버튼이 안 보임 → 화면 크기 회귀 테스트 필요
- 첨부가 많아지면 전송 버튼이 밀려 사라짐 → **목록에 MaxHeight + 스크롤**, 버튼은 항상 고정
- 흰 배경에 흰 글씨
- 창이 화면 밖에 떠서 안 보임 → 화면 안으로 자동 복귀

**핵심 기법 2개**
1. **크기를 직접 바꾸지 말고 균등 스케일** — 폭·높이를 따로 만지면 테두리가 잘린다.
2. **넘치는 건 MaxHeight + 스크롤로 흡수** — 컨테이너가 커지면서 형제 요소를 밀어내지 않게.

## 원칙 4. 같은 것이 두 번 보이면 버그다 ★ [5/6] · 약 70건

같은 정보·알림·항목·커서·선이 두 번 나타나면 **사용자는 자기가 잘못 본 걸로 착각한다.** 끝까지 추적해 없앤다.

- 한 채팅이 두 창에 동시 표시
- 같은 할일이 중복 누적
- 판서가 이중으로 그려짐 (오버레이가 캡처에도 들어감)
- 커서·선이 2개

**가장 집요하게 판 결함 — 공지 반복 표시 (4회 재수정)**:
"한 번 확인한 공지가 재접속마다 또 뜨는 것". 결론:
> **본 것은 세션이 아니라 영구히 기억한다.** (seen 기록을 로컬 세션이 아니라 영속 저장 + 재노출 차단 기간)

## 원칙 5. 지금 못 쓰는 건 숨긴다 (거절보다 은닉) ★ [5/6] · 약 65건

권한이 없거나 현재 모드에서 의미 없는 버튼·탭·필드는 **에러를 띄우지 않고 아예 안 보이게** 한다.
판서 중엔 마우스 효과가, 자리설정 중엔 메시지 버튼이 사라진다. 준비 안 된 단계의 도구는 아직 없다.

- 버튼을 눌렀을 때 "권한이 없습니다" 를 띄우는 설계 = 원칙 5 위반. 애초에 안 보여야 한다.
- 버튼을 새로 만들기 전에 **기존 버튼이 상황 인지형으로 겸할 수 있는지** 먼저 검토 (선택 없으면 A, 선택 있으면 B)
- 더 나은 해법: 버튼 자체를 없애고 **맥락 진입 시 자동으로 열기** (팀 선택 → 전송창 자동 표시)

**예외 — 위치를 기억시켜야 할 땐 숨기지 말고 죽인다**: 사용자가 "그 버튼 거기 있었는데?" 를 겪으면 안 되는 자리(완료 버튼 등)는 **숨김이 아니라 비활성(반투명·회색)**.

## 원칙 6. 모든 플랫폼이 같아 보여야 한다 ★ [5/6] · 약 65건

같은 개념(좌석·팀·파일창·로고·역할명)은 **모든 플랫폼에서 같은 색·같은 위치·같은 아이콘·같은 용어**여야 한다.
한쪽만 고친 커밋에는 곧 **"다른 쪽도 동일하게"** 가 따라붙는다 — 즉 한쪽만 고치면 작업이 두 번 된다.

- 웹/PWA 를 만들 때 데스크톱 앱의 색·배치를 **그대로 미러링**
- 한쪽 앱의 좋은 패턴은 다른 쪽으로 **차용** (인라인 회신, 아이콘 등)
- 용어도 통일 ("강사" vs "리더" 가 화면마다 다르면 안 됨)

> 단, **모바일은 축소판이 아니라 재설계**다 (자매문서 7원칙 中 6번). 토큰·개념은 같게, 터치 목표·스크롤·고정 헤더는 다시 설계.

## 원칙 7. 손이 가는 자리로 옮긴다 (배치는 판단이다) ★ [6/6] · 약 60건

기능은 그대로 두고 **위치·순서만** 바꿔 손 동선·시선·오작동 위험에 맞춘다. "정리"가 아니라 매번 판단이 들어간다.

- **위험 버튼은 손에서 멀리** — 전체 종료·재부팅 같은 파괴적 버튼을 자주 쓰는 버튼 옆에 두지 않는다
- 상태 표시는 시선이 가는 쪽, 조작 버튼은 손이 가는 쪽
- 같은 종류 아이콘은 화면마다 **같은 순서**
- 입력칸은 목록 맨 위 (스크롤 내려가서 쓰게 하지 않음)

## 원칙 8. 픽셀 단위로 수렴시킨다 [4/6] · 약 70건

"대충 맞으면 됨"을 인정하지 않는다. 실제 화면을 보고 **30px → 15px → 5px** 씩 여러 커밋에 걸쳐 수렴시킨다.
설정창 높이를 790 → 795 → 805 로 세 번 만지고, 행간을 1.5 → 1.2 → 1.4 로 왕복한다. 사용자 요청에 **-2px** 이 들어온다.

> ⚠️ **이 원칙은 AI에게 위임 불가.** 최종 수치는 CEO 가 실제 화면을 보고 정한다.
>
> **AI가 할 수 있는 것**: 첫 시안에서 **여백·정렬을 8px 그리드에 정확히 맞추고, 잘림·쏠림을 미리 제거**한다.
> 그러면 이 왕복의 **절반이 사라진다.** 그게 목표다.

## 원칙 9. 마찰 제거 — 묻지 말고, 다시 입력시키지 말고, 단계를 없앤다 ★ [5/6] · 약 55건

이미 아는 정보는 다시 묻지 않고, 결과가 뻔한 확인창은 없애고, 흐름이 끊긴 자리에서는 **끝난 뒤 원래 지점으로 자동 복귀**시킨다.

- 두 번째 로그인부터 이름 입력 스킵
- 코드를 외우게 하지 말고 **자동 감지**
- 미로그인 상태에서 어떤 동작을 시도했다면 → **로그인 후 그 동작으로 자동 복귀** (초대 링크도 마찬가지)
- 여러 단계를 **한 화면에서** 처리 (페이지 이동 없이)
- 결과가 뻔한 확인창·중복실행 안내 메시지는 **제거** (조용히 처리)

## 원칙 10. 실수는 확인창이 아니라 프리뷰 + Undo 로 막는다 [4/6] · 약 50건

"정말 하시겠습니까?" 대신 **놓기 전에 결과를 보여주고, 틀리면 Ctrl+Z**.
안전망을 *마찰*이 아니라 *되돌리기*로 만든다.

- 드래그로 자리를 바꿀 때 **놓기 전에 스왑 결과를 애니메이션으로 미리** 보여준다
- 단순 이동까지 전부 undo/redo 대상
- 삭제도 Ctrl+Z 로 복구
- 여러 종류의 실행취소가 섞이면 **통합 스택**으로 시간순 보장

**단, 과보호도 UX 결함이다**: "빈 내용으로 덮어쓰기 방지" 로직을 **제거**했다 — 사용자가 *의도적으로 비우는* 것을 막으면 안 된다.
파괴적 동작(삭제)은 **confirm 1회까지만** 허용. 이중 확인은 반려.

## 원칙 11. 사용자가 넣은 것과 하던 것은 사라지지 않는다 [4/6] · 약 50건

좌석 배치, 프리셋, 읽음 표시, **입력 중이던 답**, 창 크기, 마지막 설정, 선택 상태 —
**재접속·로그아웃·업데이트·창 재열기·비정상 종료 후에도 그대로**여야 한다.

- 재접속 시 시험 제출창 복구 + **입력 중이던 답 보존**
- 목록을 다시 그릴 때 선택을 **인덱스가 아니라 정체성(이름·ID) 기준**으로 복원 — 항목이 이동해도 따라감
- 로그아웃해도 배치가 리셋되지 않음
- 개수를 늘리거나 줄여도 기존 배치는 보존 (뒤쪽에서만 추가/제거)
- 창이 닫혀도 진행 중인 타이머·카운트는 백그라운드에서 계속
- 마지막 탭·마지막 장치 선택·분할 비율까지 기억

## 원칙 12. 키보드로 끝낼 수 있게 ★ [6/6] · 약 80건

반복 동작에는 **반드시** 키보드 경로를 만든다. 그리고 단축키는 **관용 규칙**을 따른다 (자체 규칙 발명 금지).

### 확립된 관용 규칙표

| 키 | 의미 |
|---|---|
| `Ctrl+Enter` | 전송 · 저장 |
| `Enter` | 확정 |
| `Tab` | 편집 종료 / 다음 필드 (편집 종료 시 **선택은 유지**) |
| `F2` | 이름 수정 |
| `ESC` | 한 단계 뒤로 (2단계 ESC 지원) |
| `Delete` | 삭제 |
| `Ctrl+휠` | 확대 / 축소 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 되돌리기 / 다시 |
| `Ctrl+V` | 이미지 붙여넣기 |
| 수정자 키 누르는 **동안만** | 임시 도구 전환 |
| 화살표 / `Tab` | 표·채점 그리드 내 이동 |

**한 작업이 끝난 순간, 다음 확률 높은 동작이 키 하나로 이어져야 한다.**
예: 항목 생성 → 이름 편집 자동 열림(전체선택) → `Tab` 확정 → 선택 유지 → `+` 로 다음 항목.

**반대 규칙**: 원격제어·전체화면처럼 키가 상대에게 전달돼야 하는 모드에서는 **글로벌 핫키를 차단**한다.

---

## 원칙 13. 창은 닫지 말고 앞으로 (창 관리 규칙) [4/6] · 약 55건

이미 열린 창을 다시 부르면 **닫거나 새로 만들지 말고 전면으로** 가져온다.

> **토글의 함정**: 단축키를 "열림↔닫힘 토글"로 만들면, 창이 *다른 창 뒤에 가려져 있을 때* 사용자는 "열려고" 눌렀는데 *닫힌다*.
> 올바른 동작: **뒤에 있으면 앞으로, 앞에 있으면 닫기(또는 트레이로).**

- 중복 실행 시 새 인스턴스 대신 **기존 창 강제 전면화**
- 자식 창은 부모를 따라다니고, 가까이 놓으면 **자석 도킹**, 끌어서 떼면 분리
- 도킹된 창은 부모가 움직여도 **Z-order 유지**
- 창이 화면 밖에 있으면 자동으로 화면 안으로
- 새 창은 **마우스가 있는 모니터**에 띄운다

## 원칙 14. 흐름을 끊지 마라 — 모달 → 토스트 / 인라인 [4/6] · 약 45건

작업을 중단시키는 팝업 대신 **자동으로 사라지는 토스트**나 **그 자리에서 처리하는 인라인 UI**로 대체한다.

- 완료 알림: 모달 팝업 → **우측 하단 자동닫힘 토스트**
- 채팅 알림 팝업 → **배지**로 대체
- 회신·저장 옵션 → **인라인**
- 성공 MessageBox 는 그냥 **제거**
- 초기 로딩 시 쌓인 이벤트로 **토스트 폭탄**이 터지지 않게 (초기 스냅샷은 알림 제외)

**단 두 가지 반대 규칙**:
1. **알림에는 반드시 닫기 수단**이 있어야 한다 (닫을 수 없는 알림 = 결함).
2. **놓치면 안 되는 건 강제로 시선을 끈다** — 작업표시줄 깜빡임, Topmost. 단 "항상 위"가 작업을 방해하면 **조건부로 되돌린다.**

---

## 원칙 15. 기다림·빈 상태·실패를 반드시 말해준다 [4/6] · 약 45건

로딩 중인지 실패한 건지 모르는 상태를 없앤다. 스피너 · 진행률 · **구체적** 에러 문구 · 빈 리스트 안내.

- 오래 걸리는 작업(압축·전송)은 **진행률**
- 빈 상태엔 "아직 없습니다 + 무엇을 하면 되는지"
- 실패 메시지는 구체적으로 ("오류가 발생했습니다" 금지)

**반대로 — 아직 결과가 없을 땐 실패 문구를 띄우지 않는다.**
검색 중인데 "찾지 못했습니다" 를 띄우는 것은 거짓말이다. **"선생님을 기다리는 중..."** 이 맞다.
*아직 못 찾은 것 ≠ 실패.*

**깜빡임도 결함**: 창이 빈 채로 떴다가 뒤늦게 채워지는 것 → 채우고 띄우거나, 스켈레톤을 보여준다.

---

## 원칙 16. 직접 조작 — 끌어다 놓고, 우클릭하고, 붙여넣는다 ★ [5/6] · 약 50건

"메뉴 → 다이얼로그 → 찾아보기" 경로를 **드래그앤드롭 / 우클릭 / Ctrl+V** 로 대체한다.

- 대상 위로 **파일을 끌어다 놓으면** 바로 그 대상에 첨부·전송
- **폴더**를 놓으면 알아서 압축하거나 내부 이미지만 추출
- 채팅·메모에 이미지 **붙여넣기**
- 항목 **우클릭** → 바로 실행 (폴더 열기 등)
- **끌고 있는 동안 놓을 자리를 하이라이트**로 알려준다 (원칙 10 의 프리뷰와 한 세트)

---

## 원칙 17. 진입장벽은 마지막까지 미룬다 [3/6] · 약 20건 · **후기에 집중 = 최신 방향성**

로그인·회원가입은 **정말 필요한 순간까지 미룬다.**

- **도구성 기능(판서·녹화)은 로그인 없이 동작** — 트레이 아이콘·바탕화면 메뉴에서 바로
- 열람·조회는 게스트도 가능 (게스트 전용 읽기 경로를 따로 뚫어서라도)
- 단, **벽이 아니라 미끼로 쓴다** — 완전 차단 대신 **1/3만 보여주고** 나머지는 가입 유도

# 메타 패턴 M1~M4 — CEO가 UX를 *만드는 방식*

> **원칙 17개보다 이 4가지가 시간을 잡아먹는다.** "UX 5일"의 진짜 정체.
> 강톡는 이걸 **줄이는 것**이 목표다. 없앨 수는 없다.

## M1. 같은 UX 결함을 3~6회 재수정한다 (수렴 루프)

| 결함 | 재수정 |
|---|---|
| 공지 반복 표시 | **4회** |
| 목록 창 렉 | **5회** |
| 도킹 버튼 위치 | **5회** → 결국 **버튼 자체를 제거** |
| 로그인 화면 | **5회 이상** |
| 좌석 잘림·색 | **6회 이상** |
| 버튼 위치 미세조정 | **5회 연속** (30px→15px→5px) |

→ **"됐다"고 넘기지 않는다.** 첫 구현이 60점이면 5번 만져서 95점으로 만든다.
→ 강톡의 임무: 첫 시안을 **80점**으로 올려 왕복을 5회 → 2~3회로.
→ **버튼 위치를 5번 고치고 있다면, 그 버튼이 필요 없다는 신호일 수 있다** (실제로 제거로 끝났다).

## M2. 실험 → 실제 화면에서 확인 → 아니면 즉시 revert

UI 는 코드 리뷰로 판정 못 한다. 일단 넣고, 실제 화면에서 이상하면 **같은 날 되돌린다.**
되돌린 것들: 프레임 상향(불안정), 점수 UI 개편, 커서 숨김, 과보호 로직, 무조건 Topmost.

→ **AI 는 "실제로 보고 판단"을 대신할 수 없다.** 시안이 확정이라고 우기지 마라. *되돌리기 쉬운 형태*로 내라.

## M3. UX 변경의 소스는 추측이 아니라 실사용자

커밋 메시지에 **"(사용자 요청)"** 이 직접 박힌다. **2px 단위 요청까지 반영한다.**
→ 강톡가 원칙으로 반박할 수 있는 상대는 *강디의 시안*이지 *CEO의 요청*이 아니다.

## M4. 한 커밋에 UI 수정 3~9건을 몰아 넣는다

한 커밋에 7가지·9가지 UI 수정이 함께 들어간다.
→ **실사용 세션 중 눈에 띈 것들을 모아 한 번에 친다.** "사용하면서 발견 → 일괄 수정" 루프.
→ 강톡가 결함을 보고할 때도 **묶어서** 낸다. 하나씩 흘리지 않는다.

# 강디 (designer) 지식과의 관계

`ui-designer/design-system.md` 와 `styles/` 는 **시각 토큰** (색·폰트·radius·shadow·spacing) 을 다룬다. 잘 돼 있고, **강톡는 거기 손대지 않는다.**

이 문서는 **행동 축** — 다른 축이다. 겹치지 않는다.

> 시각 토큰만 있으면: 색은 맞는데 **미접속인데 색이 안 변하고, 버튼이 독바에 가리고, 재접속하면 공지가 또 뜨는** 화면이 나온다.
> 그게 CEO 가 5일 동안 고치던 것들이다.
