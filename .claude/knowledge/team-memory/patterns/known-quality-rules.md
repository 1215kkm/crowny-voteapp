# 유명 품질 규칙 ↔ 강팀 원칙 연결 사전

> **왜 이 파일이 있나**: 강사님이 여러 레포에서 겪는 문제(탭 눌렀는데 반응 없음, 중복 기능이 따로 만들어짐 등)는 *이미 수십 년 전에 이름 붙여 정리해둔* 유명 규칙 위반이다. 강팀(특히 강톡·강디)이 화면·코드를 검사할 때 **"이건 닐슨 1번 위반이에요"** 처럼 *권위 있는 근거*를 대고 잡으라고 이 사전을 만들었다.
>
> **쓰는 법**: 강톡·강디는 결함을 지적할 때 강팀 내부 원칙 번호와 함께 *이 사전의 유명 규칙*도 같이 인용한다. "취향"이 아니라 "업계 표준"이 되면 CEO도 팀도 반박이 없다.

---

## 한눈에 — 증상 → 위반한 유명 규칙 → 강팀 원칙

| 강사님이 겪는 증상 | 위반한 유명 규칙 | 강팀 어느 원칙 |
|---|---|---|
| 탭·버튼 눌렀는데 바로 반응이 없다 | 닐슨 1(상태 가시성) + 반응속도 0.1초 법칙 | 강톡 2, 강디 7 |
| 로딩 중인지 다 됐는지 모르겠다 | 닐슨 1(상태 가시성) | 강톡 15, 강디 1 |
| 같은 일 하는 기능·버튼이 두 개다 | 닐슨 4(일관성) + DRY | 강톡 4, 강디 4 |
| 화면마다 같은 개념이 다르게 생겼다 | 닐슨 4(일관성) + 단일 진실 원천 | 강톡 6 |
| 실수로 지웠는데 되돌릴 방법이 없다 | 닐슨 3(통제·자유) + 슈나이더만 6(되돌리기) | 강톡 10 |
| 확인창이 너무 많아 흐름이 끊긴다 | 닐슨 8(미니멀) | 강톡 9·14 |
| 재접속·재시작하면 하던 게 날아간다 | 닐슨 1(상태 보존) | 강톡 11 |
| 뭘 기억해서 다시 입력해야 한다 | 닐슨 6(기억보다 인식) | 강톡 9 |
| 코드가 여기저기 복붙돼 있다 | DRY + 단일 진실 원천 | 강디 4 |

## 1. 닐슨의 10가지 사용성 원칙 (Jakob Nielsen, 1994)

이 분야의 *성경*. 화면 UX 문제의 90%가 이 10개 안에 있다.

1. **시스템 상태를 눈에 보여라** — 지금 무슨 일이 벌어지는지 화면이 항상 말해줘야. (로딩 표시, 눌린 표시, 진행률) → *탭 눌렀는데 반응 없음 = 이거 위반*
2. **시스템을 현실 세계 말로** — 전문용어 말고 사용자가 아는 말·순서로.
3. **사용자에게 통제권과 비상구를** — 실수했을 때 되돌리기(Undo)·취소가 있어야.
4. **일관성과 표준을 지켜라** — 같은 건 같아 보이고 같게 동작. 새로 만들지 말고 관례를 따라라. → *중복 기능·제각각 화면 = 이거 위반*
5. **오류를 미리 막아라** — 애초에 실수할 수 없게 설계 (못 쓰는 버튼은 비활성 등).
6. **기억하게 말고 보이게** — 외워서 입력하게 하지 말고 골라서 하게.
7. **유연성과 효율 (단축키)** — 초보는 쉽게, 숙련자는 빠르게(키보드 단축키).
8. **심미적이고 미니멀하게** — 지금 필요 없는 건 화면에서 빼라.
9. **오류를 알아보고·고치게 도와라** — 에러 메시지는 사람 말로, 해결책까지.
10. **도움말·문서** — 필요하면 찾을 수 있게.

## 2. 슈나이더만의 8가지 황금률 (Ben Shneiderman)

닐슨이랑 짝꿍. 겹치는 것도 많지만 이 4개가 특히 강하다.

1. **일관성을 유지하라** (닐슨 4와 같음)
2. **자주 쓰는 사람에겐 지름길을** — 단축키·매크로.
3. **정보성 피드백을 줘라** — 모든 동작에 반응을. → *탭 눌렀는데 조용함 = 이거 위반*
4. **동작은 완결감 있게** — 시작-중간-끝이 느껴지게 (예: 저장하면 "저장됨" 뜨기).
5. **오류를 간단히 처리** — 실수해도 쉽게 복구.
6. **되돌리기를 쉽게** — 언제든 Undo.
7. **사용자가 주도권을 갖게** — 시스템이 멋대로 하지 않게.
8. **단기 기억 부담을 줄여라** — 한 화면에 너무 많이 외우게 하지 마.

## 3. 반응속도 법칙 (얼마나 빨라야 "빠른가")

"탭 눌렀는데 바로 안 나옴" 문제의 *정확한 숫자 기준*.

- **0.1초 (100밀리초) 안** — 사용자는 "내가 직접 움직인 것"처럼 느낌. 눌린 표시는 이 안에 나와야.
- **1초 안** — 생각 흐름이 안 끊김. 단, 지연은 느낀다 → 0.1초 넘으면 *로딩 표시*라도 띄워라.
- **10초** — 사람이 집중을 유지하는 한계. 넘으면 진행률 바 필수.
- **도허티 임계값 400밀리초** — 응답이 이 아래로 떨어지면 사람이 몰입하고 생산성이 급상승. 목표선으로 삼아라.

> 핵심: *즉시 못 끝내는 건 괜찮다. 근데 "누른 것 같긴 한가?"를 0.1초 안에 알려주지 않는 건 안 된다.*

## 4. DRY 외 코드·구조 원칙

"중복 기능이 따로 만들어져 있다" 문제의 정답.

- **DRY (Don't Repeat Yourself, "반복하지 마라")** — 모든 지식·기능은 *한 곳에만*. 복붙이 보이면 냄새다. (『실용주의 프로그래머』)
- **단일 진실 원천 (Single Source of Truth) / 디자인 시스템** — 버튼·탭·색을 *한 번만 만들어 재사용*. 그럼 중복이 물리적으로 불가능. → 강디 디자인 토큰(`styles/tokens.css`)이 바로 이거.
- **SOLID** — 객체지향 5원칙 (단일 책임 / 개방·폐쇄 / 리스코프 치환 / 인터페이스 분리 / 의존 역전).
- **KISS (Keep It Simple)** — 단순한 게 최고.
- **YAGNI (You Aren't Gonna Need It)** — "나중에 쓸 것 같아서" 미리 만들지 마라. 필요할 때 만들어라.

## 강팀이 이걸로 일하는 법

1. **강톡·강디는 지적할 때 근거를 두 겹으로** — "강톡 원칙 2 위반이고, 이건 닐슨 1번(상태 가시성)이자 0.1초 반응 법칙이에요." → 취향이 아니라 표준.
2. **"매번 찾기"를 줄이는 3단계** — ①디자인 시스템으로 한 번만 만들어 중복 원천 차단 → ②린터·테스트로 자동 검출 → ③출시 전 강톡 17항 체크리스트로 훑기. 완전 자동은 아직 안 되지만, 맨땅에서 찾는 것보다 훨씬 빠르다.
3. **전수조사 패턴과 연결** — "전체 점검" 요청 시 이 사전을 잣대로 전 경로를 훑는다 (`exhaustive-audit.md` 참조).

> 출처: 닐슨 노먼 그룹(NN/g) 사용성 원칙, Shneiderman 『Designing the User Interface』, 『The Pragmatic Programmer』(DRY), Miller/Card의 반응시간 연구. 강팀 내부 원칙(강톡 17·강디 7)은 이것들을 강사님 제품 맥락에 맞게 좁힌 버전이다.
