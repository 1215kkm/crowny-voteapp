# /실시간회의

CEO 가 **회의록을 읽는 쪽이 아니라, 회의에 직접 들어와 대화하는** 모드.

기존 `/회의시작` 은 멤버 5명이 한 바퀴 돌며 회의록 HTML 을 채우는 방식이라 한 바퀴에 10분 이상 걸린다.
이 모드는 그 반대다 — **한 번에 한 명**, **짧게**, **회의록은 안 쓰고**, CEO 와 주고받는다.

```
/실시간회의                      → 아뱅과 대화 시작 (기본 상대)
/실시간회의 아뱅 인스타 홍보      → 상대·주제 지정
/실시간회의 강개발 결제 붙이기    → 다른 멤버와
```

`$ARGUMENTS` 첫 단어가 멤버 닉네임이면 그 멤버가 상대, 나머지는 주제.
**멤버 이름이 없으면 상대는 아뱅** (CEO 기본 대화 상대 — 아이디어·홍보·뒤집기 담당).

---

## 왜 아뱅이 기본인가

CEO 가 실시간으로 붙잡고 얘기하고 싶은 건 대개 *아이디어·홍보·이거 될까?* 다.
아뱅은 자문위원이라 반대·뒤집기가 본업이고, 말이 빠르고 재밌다 → 대화가 굴러간다.
설계·구현 얘기로 넘어가면 CEO 가 "강개발 불러" 하면 바로 교체된다.

---

## ⚡ 속도 규칙 (이 모드의 존재 이유 — 반드시 지킨다)

한 턴을 느리게 만드는 원인 3개를 전부 없앤다.

| 하지 말 것 | 왜 |
|---|---|
| **여러 멤버 동시 호출** | 한 턴에 **딱 한 명만** 부른다. 이게 속도의 핵심. |
| **meeting.html 쓰기·읽기** | 대화 중엔 HTML 을 만들지도 열지도 않는다. 마지막에 한 번만. |
| **agent-brief.sh 매 턴 실행** | 첫 턴에만. 2턴부터는 이전 대화 맥락만 넘긴다. |
| **긴 답변** | 멤버 답은 **3~5줄 컷**. 표·다이어그램·코드블록 금지(CEO 가 요청할 때만). |
| **파일 뒤지기** | 대화 중 멤버는 코드베이스 탐색 금지. 꼭 필요하면 CEO 에게 "찾아볼까요?" 물어본다. |

메인 클로드는 **멤버 답을 요약하지 말고 그대로 전달**한다. 대화니까.

---

## 한 턴의 모양

CEO 말 → 멤버 1명 호출 → 답을 대본체로 출력 → CEO 말 기다림. 끝.

출력 형식 (채팅에 바로, HTML 아님):

```
💡 **아뱅** "대사 3~5줄."
   *(속마음)*
```

- 닉네임 앞 이모지는 `.claude/knowledge/team-memory/personas.md` 의 멤버 이모지.
- **속마음 괄호 지문을 꼭 붙인다** — 이게 강팀 대화의 맛이고, CEO 가 아이폰 말하기로 들을 때 연기가 살아난다.
- 말투는 personas 캐릭터 시트 그대로. 아뱅이면 "오~ 재밌는데?", "야, 뒤집자!"
- 어려운 말·은어·압축 명사 금지 (CLAUDE.md 회의 톤 규칙 그대로).

---

## 대화 중 특별 명령

CEO 가 대화 도중 이렇게 말하면:

| CEO 가 하는 말 | 강팀 동작 |
|---|---|
| "다들 어때?" / "전원" / "다른 사람들은?" | **그때만** 나머지 멤버를 *한 메시지에 병렬 호출*. 각자 2~3줄. 그 후 원래 상대로 복귀. |
| "강개발 불러" / "강체크는?" | 상대를 그 멤버로 **교체**. 지금까지 대화 맥락을 넘겨준다. |
| "강톡 불러" | 강톡 합류 (선택 참석 멤버 — CEO 가 불렀으니 정당). |
| "찾아봐" / "확인해봐" | 그 턴만 멤버가 파일·코드 확인 허용. |
| "끝" / "마무리" / "정리해" | **아래 마감 의례** 실행. |

---

## 마감 의례 ("끝" 이라고 하면)

대화 중엔 아무것도 안 썼으니, 여기서 한 번에 만든다.

1. `bash scripts/start-meeting.sh "<주제>"` 로 회의 폴더·`meeting.html` 생성.
2. **지금까지의 대화 전체**를 ACT 블록으로 옮긴다 — CEO 발언도 함께. CEO 는
   `<div class="l ceo"><span class="who">CEO</span>"대사."</div>` 로 적는다
   (템플릿에 `ceo` 클래스가 없으면 `daepyo` 색을 재사용하지 말고 `.l` 기본 스타일로 둔다).
3. 화면·디자인이 대화에 나왔으면 강디가 `mockup.html` 채움.
4. 강팀장이 `SUMMARY_START ~ SUMMARY_END` 3섹션(결정/미결정/다음 액션) 작성.
5. `bash scripts/send-meeting.sh` (또는 `~/.claude/bin/send-meeting.sh`) 로 텔레그램 발송.
6. CEO 에게 한 줄: "회의록 만들었어요. 좌측 하단 ▶ 누르면 읽어줘요."

→ 이러면 실시간으로 떠든 내용이 *정식 회의록 + 읽어주기 가능한 HTML* 로 남는다.

## 🎤 타이핑 vs 음성 — 둘 다 된다

CEO 가 고르는 게 아니라 **둘 다 열려 있다.** 아무 준비도 필요 없다.

### 넣는 쪽 (CEO → 강팀)
- **타이핑**: 그냥 친다.
- **음성**: 아이폰 키보드의 **마이크 버튼**을 눌러 말한다 (기기 기본 받아쓰기).
  강팀 입장에선 타이핑과 똑같이 들어오니 따로 켤 게 없다.
  → 말로 하면 문장이 길어지고 오타가 섞이는데, **그대로 둬도 된다**. 강팀이 알아듣는다.

### 듣는 쪽 (강팀 → CEO)
- **읽기**: 채팅에 그대로 뜬다.
- **듣기 (대화 중)**: 아이폰에서 답을 **전체선택 → 말하기**. CEO 가 원래 쓰던 방법.
  ⚠️ 대화 중에는 자동 읽어주기를 못 붙인다 — 회의록 HTML 이 아직 없기 때문(속도를 위해 일부러 안 만듦).
- **듣기 (회의 끝난 뒤)**: "끝" 하면 `meeting.html` 이 나오고, 거기 **좌측 하단 ▶**
  버튼으로 멤버별 목소리·속마음 연기까지 들을 수 있다. 각 줄 앞 ▶ 로 원하는 데서 시작.

> 즉 **말로 던지고, 눈으로 받고, 끝나면 귀로 다시 듣는다.**

---

## 속도 — 솔직한 기대치

| | 한 턴 걸리는 시간 |
|---|---|
| 실시간회의 (한 명, 짧게) | **20~40초** |
| "다들 어때?" (전원 병렬) | 40~90초 |
| 기존 `/회의시작` 한 바퀴 | 10분 이상 |

GPT 음성 대화처럼 0.5초에 답하는 건 **안 된다.** 구조가 다르다 —
강팀 멤버는 각자 따로 실행되는 에이전트라 부를 때마다 시간이 든다.
카톡으로 대화하는 정도의 리듬이라고 보면 맞다.

**더 빠르게 하고 싶으면**: CEO 가 "짧게" 라고 하면 멤버 답을 2줄로 줄인다.
그 이상은 구조 한계라 못 줄인다 — 못 되는 걸 된다고 하지 않는다.

## 금지

- 메인 클로드가 아뱅 *시늉* 으로 답하기 → CLAUDE.md 절대 룰 위반. 반드시 `Agent` 툴로 `marketer` 호출.
- 대화 중 회의록 HTML 을 조금씩 채우기 → 느려진다. 마감 때 한 번에.
- 한 턴에 멤버 2명 이상 부르기 (CEO 가 "다들" 이라고 한 경우만 예외).
- 멤버 답을 메인 클로드가 요약·의역 → 대화의 맛이 죽는다. 그대로 전달.
- CEO 가 "끝" 이라고 안 했는데 마감 의례 실행.
